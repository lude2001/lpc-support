## 2. 实现约定

### 2.1 界面语言与回退

- 界面跟随 VS Code 显示语言，首版完整支持 `en` 与 `zh-cn`。英文作为默认资源，未支持的显示语言回退英文。
- 宿主、Webview、Rust sidecar 与 Efun 文档使用同一个有效语言结果。语言标记的大小写、别名和区域回退建立共享用例，避免各模块自行判断。
- 静态命令和设置使用 `package.nls.json`、`package.nls.zh-cn.json`；宿主使用 `vscode.l10n.t()` 与 `l10n/bundle.l10n.*.json`。
- 页面从宿主获得当前语言和文案资源，初次渲染、空状态、错误状态、可访问性标签和后续消息保持一致。
- 语言切换遵循 VS Code 的显示语言生命周期。本次验收在独立实例中分别启动中英文环境，不修改用户正在使用的实例。
- 运行时缺失译文采用英文回退；发布检查要求已支持的两种语言覆盖完整，不能用回退掩盖漏译。

### 2.2 Rust 消息与缓存

- Rust 继续作为语言事实的唯一真源。诊断内部保存稳定的消息标识及参数，在对外输出边界生成当前语言的文案。
- 保持诊断 `code`、`source`、范围、严重程度以及符号身份稳定；补全插入文本、跳转结果、格式化结果和快速修复编辑不受语言影响。
- 同时覆盖实时 `publishDiagnostics`、`lpc/workspaceDiagnostics`、文档中心消费的状态、悬停、签名帮助、补全说明和快速修复标题。
- 分析缓存保存语言无关的事实。现有缓存中已物化的消息和文档摘要需要迁移或失效处理；文案投影缓存按有效语言与资源版本区分。
- TypeScript 消费 Rust 已生成的诊断，不通过匹配中文句子反向翻译，也不另建解析或诊断实现。

### 2.3 Efun 数据与译文

- 函数名、签名、返回类型、参数、可选与变长标记、arity 和分类成员关系保留唯一结构数据。
- 简体中文和英文各自提供摘要、详细说明、备注、分类名称及已有参数说明；当前已经使用英文的正文也需要补齐中文。
- 采用语言资源覆盖结构数据的方式，避免复制两份完整签名。分类使用稳定 ID，将显示名称与身份分离；签名级说明需要能稳定关联对应签名及参数。
- TypeScript 文档中心与 Rust 的悬停、补全、签名帮助读取同一套语言资源和回退规则，并验证物化结果一致。
- 全部资源随 VSIX 离线提供。查询时不访问网络、不扫描工作区，也不临时调用翻译服务。

### 2.4 注释输出语言与内容边界

- 为两处注释生成增加共同的 `lpc.documentation.language` 设置，支持 `zh-cn` 与 `en`，默认 `zh-cn` 以延续已有写入行为。该设置独立于界面显示语言。
- 补全和更新已有注释时保留已有正文；用户选择的语言作用于本次新增的说明与占位内容。
- LPC 标识符、类型名、路径、宏名、Javadoc 标签、代码示例及用户源码保持原意和原文。已有 Mudlib 注释不自动翻译。
- 驱动、`lpccp`、远端服务和用户源码返回的原始信息作为原始内容展示；插件生成的状态、包装说明和操作入口提供双语。

## 4. 各里程碑工作与出口检查

### M1 基线与资源契约

工作：

1. 确认实施基线提交与本地改动，选择合适的扩展开发分支或工作树，保留其他窗口的改动。
2. 按命令与设置、宿主、页面、Rust、Efun、生成注释、片段说明建立文案覆盖表；区分用户内容与插件文案。
3. 确定 `en`、`zh-cn` 的有效语言与回退规则、占位符规范和术语表，约束 Efun、simulated efun、inherit、include 等术语的一致表达。
4. 为所有 Efun 建立结构事实基线，记录函数名、签名、参数标记、arity、分类关系及字段覆盖；新增目录布局和语言覆盖 schema 在此落定。
5. 确认 9 个静态片段说明的本地化接入方式，保证前缀、插入代码、逻辑条目键和贡献数量稳定。用户已选择保留原生片段并接受隐藏/最近使用记录按语言文件分开；原生内部 ID 含文件路径的限制见资源契约第 6 节。
6. 确定独立 VS Code 测试环境与报告目录，登记后续每项证据的来源和通过条件。

出口检查：覆盖表能追踪全部交付面；Efun 基线可机器比较；语言回退规则具备明确输入输出用例；片段接入方案可验证且不会重复注册候选。

### M2 清单与宿主本地化

工作：

1. 外置清单中的命令、视图、设置说明、枚举说明和语义 token 描述，补齐 `package.nls` 资源及 `l10n` 声明。
2. 迁移宿主的通知、对话框、按钮、选择器、输入校验、进度提示、状态、文档加载失败与 sidecar 启动错误等文案。
3. 覆盖项目配置初始化、索引重建、编译管理、诊断命令、模型选择和错误复制等实际调用链。
4. 操作分支使用稳定 ID，避免通过翻译后的按钮或选项文本判断业务动作。
5. 扩展 `tests/mocks/MockVSCode.ts` 的本地化支持，建立占位符一致性、缺键、孤立键和明确的英文回退测试。
6. 将新增资源加入构建和 VSIX 白名单，验证开发环境和打包环境均能定位资源。

出口检查：中英文调用相同命令产生相同业务动作；参数插值完整；命令 ID、设置键及枚举值保持稳定；插件自产提示无未登记的漏译。

### M3 页面完整双语

工作：

1. 文档中心覆盖标题、搜索与筛选、来源、质量状态、声明列表、详情、关系、文档操作以及空、加载、失效和错误状态。
2. 分析查看器覆盖概要、宏与条件、依赖、预处理视图、说明文字、状态和刷新入口。
3. 本地化 `lang`、`title`、`placeholder`、`aria-label`、工具提示及动态消息，确保页面初始化时即使用正确语言。
4. 保持 CSP、nonce、HTML 转义和来源验证；译文及动态参数不得成为任意 HTML 或脚本。
5. 检查英文长文本、窗口缩窄、键盘操作和焦点行为；搜索的大小写处理采用统一规则，不因显示语言改变符号身份。
6. 实现 M1 确定的片段说明接入方案，并核对候选去重及插入代码。

出口检查：两种语言的主要页面及空、加载、错误状态均有 DOM 或截图证据；筛选、跳转、刷新、搜索和文档操作行为一致；CSP 与可访问性标签继续有效。

### M4 Rust 文案与缓存

工作：

1. 从 LSP 初始化语言获得有效语言并建立集中消息目录，对缺省及不支持语言使用一致回退。
2. 将诊断的语言相关内容与事实参数分离，覆盖所有输出路径，处理现有缓存格式兼容与失效。
3. 本地化插件生成的悬停分节标题、预处理与路径补全说明、签名帮助附加说明及快速修复标题。
4. 检查常驻索引、磁盘缓存和 Efun 摘要缓存，保证两个语言会话之间没有文案污染。
5. 在 Rust 单测与 stdio smoke 中，对相同 fixture 分别以中英文初始化，比较诊断与编辑结果。

出口检查：两种语言下诊断代码、范围、严重程度和修复编辑一致，只有展示文案改变；复用同一缓存目录启动不同语言会话仍显示正确语言；查询不新增工作区扫描或重复全文解析。

### M5 全部 Efun 双语

工作：

1. 按 M1 schema 迁移结构数据和译文，完整覆盖实施基线中的全部 Efun，目前为 413 份，以及全部 23 个分类。
2. 对所有已存在的自然语言字段逐项补齐双语，包括摘要、详细说明、备注及已有参数描述。空字段不通过编造新语义补齐。
3. 结合当前维护的 FluffOS 文档校对术语、条件、参数含义、标志位、返回值和限制。参考来源记录版本或提交，保留自有扩展的事实依据。
4. 逐份校对两种语言；使用辅助翻译时必须完成语义复核。重点核对否定句、默认值、单位、位标志、成功与失败返回值以及平台限制。
5. 保留函数名、签名、示例代码和引用链接；对英文文本中的合法中文专名、源码及示例建立字段级例外说明，避免纯字符扫描误判。
6. 同时改造 `BundledEfunLoader` 与 Rust `efun_docs.rs` 的物化与缓存，供文档中心、悬停、补全和签名帮助共用。
7. 增加全量文档检查：覆盖、非空、未知键、结构指纹、分类成员关系、参数关联、引用和两个消费者的一致性。

出口检查：

- 全部 Efun 的两种语言覆盖完整，必需译文缺失数为 0；原文存在的说明全部可在对应语言中展示。
- 所有文档均完成校对登记；覆盖检查通过不能代替内容校对。
- 所有结构指纹及分类成员关系与基线一致；新增基线项有独立登记。
- TypeScript 和 Rust 对同一 Efun 的同一语言读取到相同的说明，发布资源离线可用。
- 代表性重载、变长参数、文件、对象、数据库和异步函数完成悬停、补全、签名帮助及文档中心的交叉验证。

### M6 两处注释输出双语

工作：

1. 新增并记录独立的注释语言设置，让命令面板 GLM 生成与文档中心生成、补全、更新共同消费。
2. 为 GLM 的中英文输出建立明确提示词、示例和参数契约，保留对虚构参数、遗漏返回值、截断输出和非注释输出的检查。
3. 为骨架、缺失标签和空标签填补提供两套文字模板，保留已有正文、缩进、换行和标签语法。
4. 使用模拟模型响应验证中英文输出；测试不依赖真实 API Key 或付费调用。

出口检查：覆盖“中文界面 × 英文注释”和“英文界面 × 中文注释”及同语言组合；两处入口遵从同一设置；已有正文不因界面语言变化被重写；原有生成失败保护继续通过。

### M7 统一验收与交付

工作：

1. 增加统一的本地化检查入口并纳入 CI，执行清单、宿主、Webview、Rust 与 Efun 的覆盖和插值检查。新增检查命令在实现后补入贡献文档。
2. 执行现有 TypeScript、Jest、Rust、stdio smoke 和 Efun arity 检查；新增测试验证语言差异而保留现有行为断言。
3. 用独立测试工作区与独立 VS Code 实例，在中英文环境中验收命令、设置、两个页面、语言服务、片段和注释生成，保存截图及可复核报告。
4. 对同一语料检查索引准备、Efun 加载和热请求的耗时、文件读取及解析次数，确认资源在初始化时加载，查询不增加同步资源读取或工作区扫描。
5. 更新 `README.md`、`README.en.md`、贡献文档与 `CHANGELOG.md`，说明自动语言选择、回退、注释输出设置与 Efun 双语支持。更新日志只描述相对上一版的用户可见变化。
6. 检查本机 VSIX 的语言资源和原生二进制；由现有六平台原生 CI 分别构建并验证其 VSIX，形成同一候选提交的证据。

出口检查：第 5 节全部通过；缺失或失败证据明确列出且完成修复后再核验。跨平台通过以实际 CI 结果为准。
